Halo Effect — свечение вокруг глифов

Ореол — это тень с нулевым смещением, вырезанная по альфе разложенных глифов. Своего цвета, радиуса и нулевого смещения у ThemeShadow фреймворка нет — это тень высоты, а не света, — поэтому ореол делается композицией, а не деревом XAML. И это единственное в окне, чего декларативное дерево сказать не может.

Пишется он там, где ему место: в скобках самого элемента.

TextBlock {
    u"0",
    fontSize = 48,
    HaloEffect { color = rgb(92, 138, 32), blurRadius = 14.0f },
}

Композитора в этот момент взять неоткуда: элемент ещё строится и никакому окну не принадлежит. Эффект вместо этого ждёт кадра (CompositionTarget.Rendering), пока XAML не сделает элементу собственный дочерний визуал, и берёт композитора уже у него; тогда же берётся и альфа глифов — раньше их просто нет. Кадр, а не событие элемента: о постройке своих композиционных детей XAML ничего не объявляет, а на открывшемся окне, которого никто не трогал, LayoutUpdated больше не приходит.

Дождавшись, ореол встаёт среди слоёв элемента по zIndex: отрисовка самого XAML — это 0, ореол по умолчанию лежит на -1, под глифами; положительное значение кладёт его поверх. Несколько эффектов на одном элементе упорядочиваются по тому же числу, при равном — в порядке записи.

Теги эффекта — теги свойств самой тени: color, blurRadius, opacity, offset, — плюс zIndex. Эффект — ручка: копии делят настройки, одна запись надевается на сколько угодно элементов, у каждого свои объекты композиции. Носить эффект может что угодно, умеющее отдать альфу своих глифов; ограничение так и записано: requires { element.getAlphaMask(); }.

Ореолы складываются: два на одном элементе дают тугое ядро и широкий разлёт — так сделан светодиодный индикатор ниже. Когда нужен один плотный ореол, а не два, есть GaussianBlurEffect с гаммой спада.
