# События и привязки

## Обработчики

Событие — тег: `onClick = …`. Обработчик принимает отправителя типом его
класса (`[](Button const& self) { … }`), отправителя и аргументы
(`[](Object const&, KeyRoutedEventArgs& args) { … }`) или ничего. Короткая
форма `onClick = {content = u"Thank You!"}` применяет набор присваиваний к
отправителю. Аргументы события — невладеющий и некопируемый вид указателя
ABI (`events.h`): ни счётчика, ни выделения памяти на пути, который
срабатывает на каждое движение мыши, и «только внутри обработчика» проверяет
компилятор. Обработчик не захватывает обёртку своего контрола — её отдаёт
отправитель (`try_as<T>()`).

## Ожидание события

Состояние, которое у трёх обработчиков жило бы во флагах, у корутины — счётчик
команд (`event_awaitable.h`; пример — из
`samples/Gallery/Snippets/SplitButton/Text.h`):

```cpp
auto const hideOnClick = [](Flyout flyout, Button swatch) -> async::detached_task {
    auto clicks = onClick(swatch);
    if (co_await clicks.next()) {
        flyout.hide();
    }
};
```

`onClick(button)` или `on_event<EventKey::X>(element)` — подписка-объект;
корутину возобновляет сам обработчик, прямо внутри вызова, поэтому
`args.handled(true)` ещё что-то значит. Ожидание кончается и без события:
когда элемент ушёл из дерева (`Unloaded`) и когда приложение завершается.
`co_await clicks` бросает `wxl::async::operation_canceled_exception`,
`co_await clicks.next()` отвечает значением. Токен отмены передаётся последним
аргументом: `onClick(button, stop)`.

## Модель и привязки

Поле модели — `wxl::core::observable` (`observable.ixx`): значение и событие
его изменения. `observable<T const>` — то же поле только для чтения,
`follow(источники…, функция)` вычисляет поле из других, `on_change`
подписывает на изменения. Список — `wxl::core::observable_list`. Привязка
пишется там, где описан контрол (`Bind.h`):

- `Bind{field}` — в обе стороны: контрол показывает значение, следит за ним
  и записывает правку обратно. Только для свойств, которые контрол пишет сам
  и о которых сообщает событием (пары в `binding.h`).
- `BindOutput{field}` — из поля в контрол, для любого свойства с сеттером;
  `itemsSource = BindOutput{list, build}` показывает `observable_list`, строя
  элемент на каждый пункт, и вставка пункта — одна новая строка, а не
  перестроенный список.
- `BindInput{field}` — из контрола в поле, например
  `intermediateValue = BindInput{eq.a}` у `NumberBox`: число, каким оно
  набрано, на каждую клавишу.

Направление проверяется при компиляции: свойство, которое контрол только
показывает, `Bind` отвергает и называет `BindOutput`. Безымянная
`Bind{field}` выбирает основное свойство контрола по типу данных
(`observable<bool>` у `ToggleSwitch` — `isOn`).

## Цена и границы

Привязка держит поле по адресу и не владеет им, а подписка внутри поля владеет
контролом. Модель обязана пережить свои привязки: в `samples/Quadratic` её
продлевает обработчик `wxl::Teardown`. Если модель живёт дольше окна, привязки
снимаются при закрытии окна (`unbind()`, `unsubscribe_all(…)`), иначе поле
держит контролы.
