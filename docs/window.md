# Графическая подсистема: окна, композиция и визуальные эффекты

## Точка входа и инициализация приложения

Точка входа `wWinMain` инкапсулирована внутри `wxl.ui` (`launch.h`). Цель
`wxl::ui` передаёт исполняемому файлу ключ компоновщика
`/ENTRY:wWinMainCRTStartup`. При старте процесса библиотека выполняет
следующие последовательные шаги:

1. Инициализирует среду выполнения Windows App Runtime (`bootstrap.cpp`).
2. Разворачивает интерфейсный STA-поток с ассоциированным с ним пулом памяти
   `wxl::core::sta_memory_pool`.
3. Создаёт объект приложения XAML и загружает ресурсы элементов управления.

Только после завершения этого подготовительного цикла библиотека передаёт
управление в единственную прикладную функцию — `wxl_launched()`. Разработчик
не пишет ни `wWinMain`, ни загрузчик, ни наследника класса `Application`.

## Архитектура оконной подсистемы

Библиотека предоставляет два базовых класса для управления графическими
окнами:

- **`wxl::Window`** — тонкая обёртка над стандартным классом
  `Microsoft.UI.Xaml.Window`, дополненная синтетическими свойствами для
  ограничения минимального размера (`minSize`) и восстановления положения
  окна (`placement`).
- **`wxl::CompositionWindow`** (`CompositionWindow.h`) — собственный класс
  окна верхнего уровня, создаваемый с расширенным стилем
  `WS_EX_NOREDIRECTIONBITMAP`. Данное решение полностью отключает
  стандартную промежуточную поверхность перенаправления (redirection
  bitmap), благодаря чему при динамическом изменении размеров окна за угол
  исключается появление белых просветов и артефактов
  отрисовки.

Конструкция `wxl::CompositionWindow` разделена на два независимых слоя:

1. **Нижний слой (сцена композитора).** Оперирует визуальными объектами из
   состава `Microsoft.UI.Composition`. Здесь задаётся фоновое заполнение
   (цвет или изображение, удерживаемое в кэше текстур Win2D; метод
   `backgroundAsync` загружает изображение на ходу; ожидание загрузки —
   задача, которую держит окно, и пока она ждёт, её ждёт и выход
   приложения; отказ загрузки, например при отсутствии файла, завершает это
   ожидание непрочитанным, а фон остаётся прежним), а также
   размещаются собственные визуальные элементы, отрисовываемые приложением
   самостоятельно. Изменение геометрии этих объектов происходит синхронно в
   обработчике `WM_SIZE`, и элементы держатся за рамку окна без
   отставания. Для собственной отрисовки средствами Direct2D на
   поверхности композитора предназначен компонент `wxl::DrawingSurface`.
2. **Верхний слой (остров XAML).** Поверх сцены композитора разворачивается
   прозрачный контейнер `DesktopWindowXamlSource`, занимающий всю площадь
   окна. Он обеспечивает работу стандартных элементов управления **WinUI**.
   Отрисовка строки заголовка окна выполняется силами обычных компонентов
   интерфейса, масштабирование всего острова координируется компонентом
   `wxl::ZoomEffect`, а перехват запроса на закрытие окна с возможностью
   отмены операции возложен на обработчик `onClosing`.

## Визуальные эффекты композитора

Визуальные эффекты объявляются непосредственно внутри декларативного
описания элементов управления или окон в качестве стандартных свойств и
вычисляются силами графического композитора Windows параллельно с
отрисовкой дерева XAML. Поскольку на этапе первичного конструирования
элемента интерфейса объект композитора для него ещё не инициализирован
(элемент физически не присоединён к окну), интеграция эффекта выполняется
отложенно: часть эффектов подключается на этапе первых кадров жизненного
цикла, часть — по событию `Loaded`.

| Компонент эффекта | Функциональное назначение и механизм реализации |
| :--- | :--- |
| `wxl::HaloEffect` | Реализует свечение вокруг символов. Строится на базе `DropShadow` без смещения, проецируемого на альфа-маску текста, изображения или геометрической фигуры. |
| `wxl::BevelEffect` | Формирует объёмный кант элемента: задаёт один цвет для верхней и левой граней и другой — для нижней и правой. Реализуется через `ShapeVisual` поверх целевого компонента. |
| `wxl::MagnifyEffect` | Выполняет динамическое масштабирование (увеличение или сжатие) элемента при наведении указателя. Изменение геометрии привязано к фиксированному интервалу времени, а не к расстоянию до центра. |
| `wxl::GlassEffect` | Эффект матового стекла под элементом. Выполняет тонирование и размытие того, что находится за ним, как в пределах острова XAML, так и на сцене композитора окна. |
| `wxl::Button3DEffect` | Изображает кнопку объёмной клавишей под лампой. Форма клавиши задана картой нормалей, которую освещает композитор через `SceneLightingEffect`: далёкая лампа, общий свет и две лампы над указателем; на панель клавиша отбрасывает проецируемую тень композитора. |
| `wxl::GaussianBlurEffect` | Свечение вокруг глифов с затуханием, настраиваемым прикладной логикой. |
| `wxl::RevealEffect` | Интерактивное освещение, следующее за указателем. Формирует световое пятно на целевом элементе и подсвечивает границы смежных компонентов интерфейса. |
| `wxl::FocusEffect` | Собственная визуализация фокуса ввода с клавиатуры, выдержанная в стилистике окна взамен стандартной системной рамки. Назначается на уровень окна. |
| `wxl::ZoomEffect` | Управляет масштабированием всего острова XAML с клавиатуры и колеса мыши. Назначается на уровень `wxl::CompositionWindow`. |

Исходники эффектов — `wxl.ui/src/<Имя>.h`. Полный каталог реализованных и
запланированных визуальных решений доступен в документе
[«Эффекты современного GUI — каталог»](effects-catalog.md).

## Границы применимости и компромиссы

В силу стиля `WS_EX_NOREDIRECTIONBITMAP` до отрисовки первых элементов сцены
композитора окно полностью прозрачно. По этой причине цвет фона или
изображение обязаны устанавливаться до показа окна.

Архитектура подсистемы исключает дублирование тяжёлых ресурсов в памяти:
фоновое изображение существует как единственный визуальный объект на сцене
композитора, без копии в дереве элементов XAML.

Конструктор `wxl::CompositionWindow` зависит от библиотек Win2D во время
выполнения, так как внутри него создаётся разделяемое графическое устройство
`CanvasDevice`. В случае отсутствия необходимых DLL рядом с исполняемым
файлом конструктор завершится ошибкой. Копирование всех сопутствующих
динамических библиотек в выходной каталог обеспечивается функциями CMake
(см. раздел [«Сборка и верификация»](building.md)).
