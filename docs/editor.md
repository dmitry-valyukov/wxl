# Настройка среды разработки

## Поддержка IntelliSense в VS Code для модулей C++

**Проблема.** При стандартной конфигурации среды разработки импорт партиций
модулей (`import :partition;`) ошибочно подсвечивается редактором как
синтаксическая ошибка. Причина заключается в текущих ограничениях
инструментария сборки модулей: расширение C/C++ от Microsoft способно
считывать скомпилированные интерфейсы модулей (`.ifc`) только при явной
передаче флага `/reference <имя_модуля>=<путь>`. В то же время CMake
инкапсулирует эти ключи во внутренние файлы ответов `*.obj.modmap`,
оставляя в `compile_commands.json` лишь ссылку вида `@path/to/file.modmap`,
которую `cpptools` обрабатывать не умеет. Провайдер конфигурации CMake Tools
данные ключи компилятора также не передаёт.

**Область применения.** Описанный ниже алгоритм ориентирован на модуль
`wxl.core`, открытый в VS Code отдельной рабочей директорией и
сконфигурированный собственными пресетами: `cmake --preset x64` и
`cmake --build --preset x64-debug` (каталог сборки — `wxl.core/build/x64`).
Скрипт автоматизации генерирует файл конфигурации
`wxl.core/.vscode/c_cpp_properties.json`. Автоматический запуск скрипта
после сборки по умолчанию отключён и включается ключом CMake
`WXL_UPDATE_INTELLISENSE=ON` при настройке `wxl.core` отдельно.

**Алгоритм настройки:**

1. Выполнить сборку проекта для генерации актуальных интерфейсных файлов
   `.ifc` (конфигурация по умолчанию — `Debug`).
2. Запустить генератор конфигурации IntelliSense командой:

   ```
   pwsh wxl.core/tools/gen-intellisense-config.ps1
   ```

   Для другой конфигурации предусмотрен флаг `-Config Release`, для другого
   каталога сборки — `-BuildDir`. Скрипт проанализирует все сгенерированные
   файлы `*.obj.modmap`, развернёт относительные пути и сформирует директивы
   `/reference` в файле `.vscode/c_cpp_properties.json`.
3. Если подсветка синтаксиса в редакторе не обновилась автоматически,
   выполнить команду «C/C++: Restart IntelliSense for Active File» или
   перезагрузить окно VS Code.

Если ключ `WXL_UPDATE_INTELLISENSE=ON` задан, ручной запуск второго шага
требуется произвести однократно: в дальнейшем генератор вызывается
автоматически после каждой успешной компиляции `wxl.core` (post-build шаг).
Автоматический запуск срабатывает только при условии, что сборка
инициирована из среды разработки. Индикатором служат переменные окружения,
выставляемые IDE для дочерних процессов (например, `VSCODE_PID` для VS Code
или `VSAPPIDNAME`/`VSAPPIDDIR` для Visual Studio). Окружение консоли
Developer Command Prompt признаком IDE не считается (переменные
`VisualStudioVersion` и `VSINSTALLDIR` выставляются штатным сценарием
`vcvars64.bat`), поэтому сборки через терминал или на CI-серверах
конфигурационные файлы редактора не изменяют. Лог выполнения автоматизации
записывается в файл `wxl.core/build/x64/intellisense-config.log`.

Конфигурация IntelliSense обновляется под ту конфигурацию, которую только
что собрали: при сборке в режиме Release редактор переключается на чтение
`.ifc`-файлов из каталога Release.

**Важное ограничение.** Не следует соглашаться на предложение VS Code
переключить проект на использование CMake Tools в качестве
`configurationProvider`. В этом сценарии расширение `cpptools` начинает
игнорировать массив флагов `compilerArgs` из файла `c_cpp_properties.json`,
переходя на данные от провайдера, из-за чего директивы `/reference`
перестают доходить до подсистемы IntelliSense.

Для корректной работы требуется расширение C/C++ версии, поддерживающей
чтение актуального бинарного формата `.ifc` (для набора инструментов MSVC
14.51 используется формат IFC 0.44, поддержка которого появилась начиная с
pre-release версий 1.33.x).

**Известный побочный эффект.** В процессе работы расширение `cpptools`
удерживает дескрипторы прочитанных `.ifc`-файлов открытыми. Это может
приводить к сбоям инкрементальной сборки с ошибкой компилятора
`error C3474: could not open output file '….ifc'`. Проблема устраняется
освобождением файлов через перезапуск IntelliSense («C/C++: Restart
IntelliSense for Active File» или перезагрузка окна редактора), после чего
компиляция продолжается штатно.
