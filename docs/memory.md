# Память одного потока

**Задача.** Интерфейс непрерывно создаёт и разрушает мелкие объекты —
звенья `Impl`, узлы событий, кадры корутин, деревья разметки — и всё это в
одном потоке. Общая куча платит за многопоточность, которой здесь нет.

## Как устроено

`wxl::core::sta_memory_pool` (`sta_allocator.ixx`, `sta_allocator.cpp`):

- Классы размеров — степени двойки, от указателя до 32 КиБ. Номер класса —
  `std::countl_zero(size - 1)`, то есть `lzcnt`; для размера, известного при
  компиляции (`alloc<sizeof(T)>()`), номер — константа. Без `/arch:AVX2`
  `std::countl_zero` из STL MSVC добавляет проверку наличия инструкции
  (`wxl.core/benchmarks/CMakeLists.txt`).
- Блоки нарезаются сдвигом курсора по страницам в 1 МиБ (`VirtualAlloc`);
  освобождённый блок ложится в интрузивный список своего класса. Остаток
  страницы при переходе на новую нарезается на классы и не пропадает.
- Вызов идёт через таблицу функций по классам, и слот переписывает себя сам:
  пока у класса нет освобождённых блоков, слот указывает прямо на выделение
  сдвигом курсора и список не проверяется вовсе; первое освобождение
  переводит слот на снятие из списка, опустевший список — обратно. Сплошные
  выделения — ровно то, что происходит при построении дерева интерфейса.
- Больше 32 КиБ — своя куча потока (`wxl::core::thread_heap`), больше
  половины страницы — `std::malloc`.
- Ни блокировок, ни атомарных операций; в Debug каждая точка входа
  проверяет поток. Пул — статический объект в сегменте инициализации `lib`,
  поэтому он стоит раньше первого объекта программы и уходит после
  последнего.

Пулом пользуются `wxl::core::sta_refcounted` (звенья `Impl`), кадры корутин
`wxl.async`, узлы событий, арены `wxl.xml` и `wxl.html`; контейнерам —
`wxl::core::sta_allocator`.

Схема выбрана замером: вариант, где слот не переписывается и каждое
выделение проверяет список, заметно проигрывал на сплошных выделениях и
ничего не выигрывал на реальной нагрузке. Стенда с вариантами в дереве нет;
о пуле подробно — [статья 2](https://habr.com/ru/articles/1082702/). Нынешний
пул в абсолютных числах меряет `wxl.core.sta-get-benchmark`, сравнение с
обычной кучей печатают `wxl.core.sta-allocator-benchmark` и
`wxl.core.sta-scenario-benchmark`.

## Пустое значение без лишнего байта

`wxl::core::nullable` (`compressed_optional.ixx`) выбирает представление через
`wxl::core::optional_selector`: значение-страж из концепта `sentinel` вместо
флага `bool`. У целого со знаком страж — наименьшее значение, у беззнакового —
наибольшее, у числа с плавающей точкой — NaN, у указателя и обёртки wxl —
пустой указатель, у `exception_ptr` — пустой. Интерфейс — как у
`std::optional`: `value_or`, `and_then`, `transform`, `or_else`. Цена — страж
вынут из диапазона: где допустимо любое значение (код возврата процесса в
`launch.h`), пишется `std::optional`. У `bool` лишнего значения нет, и
`nullable<bool>` — это `std::optional<bool>`.

## Цена и границы

Память принадлежит потоку: выделенное в нём там же и освобождается, а
объект, который считают несколько потоков, наследует
`wxl::core::refcounted_mt` и живёт в обычной куче. Класс размера — степень
двойки, так что блок бывает почти вдвое больше запрошенного. Страницы пула
возвращаются системе только при завершении процесса.
