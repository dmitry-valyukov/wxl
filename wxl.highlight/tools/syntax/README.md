# Свои языки подсветки

Языки, которых у RsdnFormatter нет, а на форуме они называются: `[js]`,
`[ts]`, `[css]`, `[go]` и то, что подсвечивает сам сайт (highlight.js:
`lua`, `cmake`, `bash`, `json`). Формат файла — тот же, что у
RsdnFormatter (`Format/CodeFormat/Syntax/*.json`), чтобы генератор
`../import-syntax.ps1` читал оба источника одинаково:

```json
{
  "name": "Go",            // имя языка и заодно основа имён в C++
  "displayName": "Go",
  "options": "(?n)",       // с буквой i — язык без учёта регистра
  "patterns": [
    { "name": "kw", "type": "keyword",
      "prefix": "WordBoundary", "postfix": "WordBoundary",
      "keywords": [ "func", "range" ] }
  ]
}
```

Порядок слов не важен: генератор сам сортирует их по кодовым единицам и
складывает регистр там, где язык его не различает.

**Комментариев и строк здесь нет.** Они описаны в самом генераторе, в
таблице `$Delimiters`, и заданы парами «открыл — закрыл», а не
регулярными выражениями: у комментария до конца строки закрывающей пары
нет вовсе, у внутристрочного она любая, а у построчного (`=begin` в Ruby)
открывающая обязана стоять в начале строки. Совпадающие куски там общие —
сишные `//` и `/* */`, решётка shell, кавычки, — и язык собирает свой
набор из них.

Чего в этих таблицах нет и не будет: `diff` и `http` — у них раскраска
идёт по началу строки, а не по словам; `dos` — там комментарий
открывается словом `rem`, а у правил «открыл — закрыл» границ слова нет;
`avrasm` — это свой набор инструкций, и наш `Assembler` (x86) выдал бы
чужие мнемоники за свои.
